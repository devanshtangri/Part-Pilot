## Completed backend contract

`GET /api/parts` accepts an optional protected `search` parameter while
preserving:

- `part_type_id`;
- `location_id`;
- `limit`;
- `offset`;
- active-only results;
- accurate total metadata.

Search covers:

- part number and name;
- description, package, and notes;
- part type name and description;
- manufacturer and location;
- aliases and tags;
- custom-field keys and labels;
- typed custom text, numeric, JSON, unit, and boolean values.

Search is case-insensitive and partial. SQL wildcard characters are literal.
Correlated existence queries prevent duplicate result rows.

## Result ordering

For searches:

1. parts with positive available quantity come first;
2. exact part-number matches;
3. part-number prefix matches;
4. exact name matches;
5. name prefix matches;
6. newest update and stable ID ordering.

Out-of-stock matches therefore remain available to the frontend but appear
after available parts.
