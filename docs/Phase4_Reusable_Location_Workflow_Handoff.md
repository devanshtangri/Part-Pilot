## Mandatory patch workflow

Every diagnostic, fix, and implementation must be supplied as a complete
Python file. Never require manual source editing.

Every implementation script must:

1. Verify exact repository prerequisites and Git state.
2. Preflight all browser-test source transformations entirely in memory before
   backups or application writes.
3. Back up every changed file.
4. Keep the implementation narrowly scoped.
5. Compile Python where applicable.
6. Run `git diff --check`.
7. Build and deploy Part Pilot.
8. Verify Alembic head and current revision.
9. Run the complete smoke suite.
10. Verify deployed frontend markers and relevant routes.
11. Roll back safely on failure.
12. Print the exact final line `Everything PASS` only after all intended
    operations and checks succeed.

Use headings:

- `Browser test — Patch N` when manual browser testing is required.
- `Fix only — Patch N` when terminal verification is sufficient.

Terminal `Everything PASS` and browser approval are separate. Never commit a
browser-dependent implementation until the user explicitly approves it.

The user prefers frequent meaningful Git commits:

- commit independent backend batches after terminal verification;
- commit browser-dependent batches immediately after browser approval;
- keep implementation and documentation commits separate when practical;
- do not create artificial commits for failed or no-op patches.
