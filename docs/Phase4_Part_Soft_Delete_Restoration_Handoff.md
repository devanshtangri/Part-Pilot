## Completed part lifecycle workflow

### Backend

Protected endpoints:

- `DELETE /api/parts/{part_id}`
- `POST /api/parts/{part_id}/restore`
- `GET /api/parts/deleted`

Soft deletion:

- sets `is_deleted=true`
- sets `deleted_at`
- hides the record from normal reads
- preserves the part row
- preserves metadata
- preserves total and reserved quantities
- preserves typed field values
- preserves stock movements
- preserves manufacturer, package, and part type
- preserves the globally unique part number

Restoration:

- sets `is_deleted=false`
- clears `deleted_at`
- restores normal list/detail/movement visibility
- keeps all preserved data intact
- returns 409 for invalid repeated or conflicting transitions

Audit events:

- `part.deleted`
- `part.restored`
- authenticated actor
- complete before/after lifecycle snapshots
- retained field-value and movement counts
- preserved quantity metadata

No migration was required because the model already contained lifecycle state.
