Patch and chat workflow
- Every change is one complete sequential downloadable Python patch.
- The assistant provides the file in chat only; it does not place or execute it
  on the HomeLab. The user copies it to fixes/ and runs it.
- Filenames begin with the number, never patch_. Failed user-run scripts consume
  their number. Successful scripts end with exactly `Everything PASS`.
- Use headings `Patch N - Browser Test` or `Patch N - Fix Only`.
- Browser instructions stay outside scripts. Browser-test source stays unstaged
  and uncommitted until explicit approval; a separate checkpoint commits/pushes.
- Chat 14 is `Chat 14: Projects Foundation`, owns Patch 366-395, and Patch 395
  is its planned boundary. No next-chat prompt files are created.

Efficient HomeLab use
- Use HomeLab read-only inspection only for critical state, uncertain source,
  high-risk transforms or checkpoint verification. Avoid repetitive commands.
- Local source, Git/index state, newest successful logs and deployment are
  authoritative. Do not assume GitHub represents pending work.
- Generate every transform in memory before backup/write. Prefer exact hashes,
  scoped blocks and semantic markers over brittle adjacency anchors.
- Do not run or preflight a numbered patch unless the user explicitly asks.

Patch safeguards
- Validate repo, branch, origin, HEAD/origin, empty index, exact pending
  allowlist, source hashes, prerequisites and successful prior logs.
- Backups: /projects/Part Pilot/fixes/backups/
- Logs: /projects/Part Pilot/fixes/logs/ (ignored by Git)
- Durable diagnostics: docs/diagonostic_*.md
- Failure output includes phase, exception, actual command or in-memory source
  transformation, useful output, rollback result, final Git state and log path.
- Application patches verify Python/TypeScript, git diff --check, Docker
  build/deploy, Alembic, protected APIs, SPA routes/bundle markers, complete
  copied-database smoke and live-data preservation.
- Stage only explicit allowlists; staged diff --check; push main; fetch and
  verify local HEAD equals origin/main.
- Keep docs/Part_Pilot_Project_Memory.txt at or below 8,000 characters.

Inventory and user-data safety

- Cleanup only fixture-owned records; preserve real inventory and history.
