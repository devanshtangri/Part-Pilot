Patch workflow
- Every implementation/fix/diagnostic/docs/checkpoint/commit/push/boundary/handoff is one sequential Python file under `fixes/`; filename starts directly with the patch number. Failed executed scripts consume numbers. Successful final line exactly `Everything PASS`.
- User normally runs numbered patches. Assistant may execute one only when explicitly asked to run that exact patch; then run the exact command once and return raw terminal output only, with no diagnosis/retry/extra commands.
- Before writes validate repo/root, branch, verified origin identity, committed HEAD, exact index/source bytes, prerequisites and transforms. Backups `fixes/backups/`; logs `fixes/logs/`; diagnostics `docs/diagonostic_*.md`. Avoid brittle whitespace anchors.
- Browser-test app source remains uncommitted/unpushed until explicit approval. Browser instructions stay outside patch scripts. After approval create a separate checkpoint/commit/push patch promptly.
- App changes require `git diff --check`, relevant compile/build, canonical Docker build, Alembic validation, copied-production/relevant smokes, protected APIs, SPA/runtime markers and real-data preservation. Rehearsals stay isolated from live source/deployment.
- Stage only an exact allowlist; verify staged diff/check; push `main`, fetch and verify local HEAD == `origin/main`. After two consecutive pre-write failures/repeated anchor mismatch/uncertain pending source, diagnostic-only next.
- Origin spelling must match the verified configured remote; Patch 767 proved equivalent HTTPS-vs-SSH spelling can cause a false preflight failure. Repo memory target <=20,000 characters. Newest handoff + local repo state are authoritative for volatile hashes/runtime/pending state.
- Patch delivery order: heading; file/path; SHA-256; scope/source-build-browser-commit status; exact run command; expected `Everything PASS`. For AI/MCP browser tests provide exact copy-paste prompts.

Product/UI rules
- Flat dense enterprise UI; subtle borders, restrained radii, readable spacing and responsive behavior; no gradients/glow/glass/decorative imagery. Prefer themed controls. Disabled = not-allowed; wait/busy only during actual loading/saving.
- Preserve search/filter/sort/pagination/stale-request guards/selection/history/edit/delete/restore behavior through layout changes; explicitly test intermediate/mobile widths.
- Low-risk reversible Preferences may autosave with rollback/stale-request protection. Credentials/password/delete/purge/revoke/rotate/backup-restore/lifecycle transitions require explicit actions/confirmation.
- Currency is formatting/display only and timezone is passive timestamp display only; neither rewrites historical prices/currency snapshots/stored timestamps.

MCP/OAuth/direct access
- OAuth discovery/DCR/PKCE/consent/token/refresh/revocation and stateless `/mcp`; real Claude/ChatGPT flows verified. Scope challenges reflect enabled categories; existing tokens never silently gain `mcp:write`.
- Named direct clients support Bearer/custom-header/trusted-network auth. No-auth is off by default, typed-confirmed, read-only and lower precedence than explicit credentials/trusted networks.
- Global individual-tool permissions + per-client deny ceilings + server/read/write category gates apply at discovery and call time. Permission booleans remain mutable configuration.
- Safeguarded writes reuse canonical services and require server/write/global/client/scope ceilings, active Operator-or-higher authority, preview, short-lived confirmation, idempotency/completed replay and state-drift rejection. No-auth stays read-only.
- Writes: `reserve_project`, `consume_reservation`, `cancel_reservation`, `adjust_part_quantity`, `create_part`, `update_part_metadata`, `soft_delete_part`, `restore_part`. Permanent purge/hard delete/recycle-bin emptying is deliberately absent from MCP.
- `update_part_metadata` is complete explicit metadata replacement and cannot change stock. `soft_delete_part`/`restore_part` reuse recycle-bin services, preserve quantities/reservations/fields/movements/history and create no stock movement solely for lifecycle change. History shows connected MCP client identity while retaining backing user accountability.
