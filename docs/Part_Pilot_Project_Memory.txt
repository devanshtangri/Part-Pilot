Patch and chat workflow
- Every implementation, fix, diagnostic, checkpoint, cleanup and documentation
  update is one complete downloadable Python file supplied in chat. The
  assistant does not place or execute numbered patches on HomeLab unless
  explicitly asked.
- Filenames start directly with the sequential patch number, never patch_.
  Failed user-run scripts consume their number.
- Successful scripts print exactly `Everything PASS` as their final line.
- Response headings are `Patch N - Browser Test` or `Patch N - Fix Only`.
- Chat 15 is `Chat 15: Project Lifecycle Completion`, owns Patch 397-426, and
  Patch 426 is its planned boundary. Patch 417 checkpoints browser-approved
  global appearance; Patch 418 is the next focused Settings refinement.
- Browser-test source remains unstaged/uncommitted until explicit approval,
  followed by a separate checkpoint/commit/push script.
- No next-chat prompt file is created. A ready prompt is posted only after a
  successful boundary.
- After two consecutive pre-write failures, repeated anchor mismatches or
  source uncertainty, issue the next diagnostic-only patch and create
  docs/diagonostic_*.md.

HomeLab-assisted safeguards
- Inspect exact Git/index state, hashes, logs, deployment, OpenAPI/bundle
  markers and live SQLite values before high-risk patches.
- Local source and newest durable diagnostic/handoff are authoritative.
- Generate transformations in memory before backup/write; prefer exact hashes,
  scoped functions/markers and semantic validation over adjacency.
- Backups: /projects/Part Pilot/fixes/backups/
- Logs: /projects/Part Pilot/fixes/logs/ and ignored by Git.
- Application changes compile, run git diff --check, build/deploy, verify
  Alembic/protected APIs/SPA markers, run complete smoke on a copied database
  and preserve live data.
- Failure output includes phase, exception, actual command or in-memory
  transformation, rollback result, final Git state and log path.
- Checkpoints stage explicit allowlists only, validate staged diff, push main,
  fetch and verify local HEAD equals origin/main.
- Keep this memory at or below 8,000 characters.

Inventory and fixture safety
- Never assume an empty database. Use unique manifest-owned fixtures and clean
  up only recorded IDs.
- Preserve users, catalogues, inventory, Projects, Reservations, movements,
  audits and settings. SQLite integrity and foreign-key checks must pass.
- Six realistic Patch 401 test parts remain intentionally in the test database.
  Manifest: /projects/Part Pilot/fixes/logs/patch_401_test_fixture_manifest.json
- The user plans to reset the database before production use. Do not silently
  remove fixtures/history before explicit cleanup or reset.
