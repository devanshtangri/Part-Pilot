Patch and chat workflow
- Every implementation, fix, diagnostic, checkpoint, cleanup, documentation
  update and boundary is one complete downloadable sequential Python file.
- Filenames begin with the number, never patch_. Failed user-run scripts
  consume their number. Successful scripts end with exactly `Everything PASS`.
- Browser-test source remains unstaged/uncommitted until explicit approval,
  followed by a separate checkpoint/commit/push script.
- Chat 16 is `Chat 16: Backup and Restore Foundation`, owns 427-456;
  failed boundary Patch 457 is consumed and recovery is Patch 457.
- Chat 17 is `Chat 17: Backup Status Finalization and MCP Foundation`, owns
  458-487 and Patch 487 is its planned boundary.
- No next-chat starting-prompt file is created. The ready prompt is posted
  only after the boundary script ends with `Everything PASS`.
- After two consecutive pre-write failures, repeated anchor mismatches or
  source uncertainty, issue a diagnostic-only patch and create a
  `docs/diagonostic_*.md` report.

  SQLite and staging before high-risk patches.

  hashes, scoped structures and semantic/minifier-safe validation.
- Backups: /projects/Part Pilot/fixes/backups/

  final Git state and log path.

  fetch and prove local HEAD equals origin/main.
- Keep this file at or below 8,000 characters.
