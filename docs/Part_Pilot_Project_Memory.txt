Patch workflow
- Every change is one complete sequential Python patch file.
- The assistant may place patch files directly in /projects/Part Pilot/fixes/;
  the user executes them.
- Failed scripts consume their patch number. Never reuse one.
- Filenames begin directly with the number, never patch_.
- Success prints exactly `Everything PASS` as the final line.
- Validate repository, origin, HEAD, index, pending source and transforms before
  backup/write. Print simple progress phases.
- Backups: /projects/Part Pilot/fixes/backups/
- Logs: /projects/Part Pilot/fixes/logs/
- Diagnostic Markdown filenames start with `diagonostic_`.
- Failure output includes phase, exception, actual command, useful output,
  rollback, final Git state and log path.

Failure escalation
- After two consecutive pre-write failures, repeated anchor mismatches, or
  uncertainty about pending source, issue a diagnostic-only patch.
- Split unrelated backend, frontend, CSS, smoke and checkpoint work.
- Never reset, overwrite, stage or commit browser-test source before approval.
