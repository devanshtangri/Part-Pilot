Patch and chat workflow
- Every implementation, fix, diagnostic, checkpoint, cleanup and documentation
  change is one complete sequential downloadable Python patch.
- The assistant provides the file in chat only; it does not place or run it on
  HomeLab. The user copies it to fixes/ and runs it.
- Filenames begin with the patch number, never patch_. Failed user-run scripts
  consume their number. Successful scripts end with exactly `Everything PASS`.
- Use headings `Patch N - Browser Test` or `Patch N - Fix Only`.
- Browser instructions stay outside scripts. Browser-test source remains
  unstaged/uncommitted until explicit approval and a separate checkpoint.
- Chat 14 planned boundary Patch 395 failed before writes; narrow boundary
  recovery Patch 396 closes the chat.
- Chat 15 is `Chat 15: Project Lifecycle Completion`, owns Patch 397-426, and
  Patch 426 is its planned boundary.
- No next-chat prompt files are created. The ready prompt is posted in chat only
  after a successful boundary.

HomeLab-assisted workflow
- Inspect exact local Git/index state, source hashes, successful logs,
  deployment, HTTP contracts and live SQLite values before high-risk patches.
- Local source and newest diagnostic/handoff are authoritative.
- Generate every transform in memory before backup/write. Prefer exact hashes,
  scoped functions/markers and semantic counts over brittle adjacency.
- Do not run or preflight numbered patches unless the user explicitly asks.
- After two consecutive pre-write failures, repeated anchor mismatches or source
  uncertainty, stop implementation and issue a diagnostic-only patch under
  docs/diagonostic_*.md.

Patch safeguards
- Validate root, branch, SSH origin, HEAD/origin, index, exact pending allowlist,
  current hashes, prerequisites and prior log evidence.
- Backups: /projects/Part Pilot/fixes/backups/
- Logs: /projects/Part Pilot/fixes/logs/ (ignored by Git)
- Application patches verify Python/TypeScript, git diff --check, Docker
  build/deploy, Alembic, protected APIs, SPA routes/bundle markers, complete
  copied-database smoke and live-data preservation.
- Failure output includes phase, exception, actual command or in-memory
  transform, useful output, rollback result, final Git state and log path.
- Stage only explicit allowlists; staged diff --check; push main; fetch and
  verify local HEAD equals origin/main.
- Keep this file at or below 8,000 characters.

Inventory and data safety
- Never assume an empty database. Use unique fixture-owned IDs and cleanup only
  those IDs.
- Preserve real inventory, Reservations, Projects, movements, audits, settings
  and catalogue data.
- SQLite integrity and foreign-key checks must pass.
