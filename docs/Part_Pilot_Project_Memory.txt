Patch workflow
- Every implementation, fix, diagnostic, cleanup, documentation update,
  checkpoint, commit, push and handoff is one complete downloadable Python file.
- Never require manual line edits.
- Patch numbers are sequential and consumed when run, including failures.
- Filenames begin directly with the number, never patch_.
- Success prints exactly `Everything PASS` as the final line.
- Validate repo, branch, origin, HEAD, index, pending source and transforms
  before backup/write.
- Backups: /projects/Part Pilot/fixes/backups/
- Logs: /projects/Part Pilot/fixes/logs/
- Diagnostic Markdown filenames start with exact prefix `diagonostic_`.
- Failure output includes phase, exception, command, useful output, rollback,
  final Git state and log path.

Failure escalation
- After two consecutive pre-write failures, repeated anchor mismatches, or
  uncertainty about pending source, issue a diagnostic-only patch.
- After repeated failures, split work into small independent chunks. Do not
  combine unrelated smoke, CSS, backend and checkpoint work.
- Diagnostic commits may include only their report while pending app bytes and
  index remain unchanged.
