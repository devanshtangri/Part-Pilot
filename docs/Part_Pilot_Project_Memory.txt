Patch workflow
- Deliver every implementation, fix, diagnostic, cleanup, documentation update,
  checkpoint, commit, push and handoff as one downloadable Python file.
- Never require manual line edits.
- Use one sequential patch number; never reuse a number after its script ran.
- Filenames begin with the number, never `patch_`; filename and run command match.
- Successful scripts print exactly `Everything PASS` as their final line.
- Validate repo, branch, origin, source state, prerequisites and all transforms in
  memory before backup/write. Anchor mismatch must fail without touching source.
- Backups: /projects/Part Pilot/fixes/backups/
- Logs/reports: /projects/Part Pilot/fixes/logs/
- Diagnostic Markdown filenames start with exact prefix `diagonostic_`.
- Failure terminal output includes phase, exception, failing command, useful
  stdout/stderr, rollback result, final Git state and log path.
- Run git diff --check. Compile relevant Python. For application changes build,
  deploy, verify Alembic, complete smoke suite, protected APIs, SPA routes,
  deployed markers and inventory preservation. Restore source/deployment on fail.

Browser workflow
- Never put browser instructions inside patch scripts.
- Terminal `Everything PASS` means automated checks only.
- Give browser instructions separately when required.
- Keep browser-test source uncommitted/unpushed until explicit approval.
- Apply feedback in the next sequential script; checkpoint/commit/push separately.
