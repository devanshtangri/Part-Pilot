Patch workflow
- Every implementation, fix, diagnostic, documentation update, checkpoint,
  commit, push and boundary is one complete downloadable sequential Python file.
- Filenames begin directly with the patch number. Failed user-run scripts
  consume their numbers. Success ends with exactly `Everything PASS`.
- Validate exact repo, branch, HEAD/origin, Git/index, source hashes,
  prerequisites and in-memory transforms before writes.
- Backups: /projects/Part Pilot/fixes/backups/
- Logs: /projects/Part Pilot/fixes/logs/
- Diagnostic Markdown prefix: `diagonostic_`.
- Application patches build/deploy, verify Alembic, protected APIs, SPA routes,
  complete copied-database smoke, live-data preservation and rollback.
- Browser-test source stays uncommitted until approval, followed by a separate
  checkpoint patch.
- After two consecutive pre-write failures, repeated anchor mismatches or
  source uncertainty, stop and issue a diagnostic-only patch.
- Keep this file at or below 8,000 characters.
- Never execute numbered patch scripts for the user.
