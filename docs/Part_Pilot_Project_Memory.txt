Core workflow:
Every implementation, fix, diagnostic, cleanup, documentation update, checkpoint, commit, push, and handoff must be delivered as one complete downloadable Python file. Never ask the user to find exact lines and copy-paste manual edits.

Use one sequential patch number for every operation. Never reuse a number after the corresponding script has been run. A corrected replacement may keep the same number only when the earlier file was not run.

Every successful script must print exactly:
Everything PASS
as its final output line. Never print that line on failure.

Every script must verify the repository, branch, origin, expected source state, and prerequisites. Validate all planned transformations in memory before creating backups or writing files. If source anchors do not match, fail before touching the working tree.

Back up every changed file under:
/projects/Part Pilot/fixes/backups/

Store logs and diagnostic reports under:
/projects/Part Pilot/fixes/logs/

Keep terminal output concise. Save full diffs to the log instead of printing large source files. Run git diff --check. Compile relevant Python files. Build and deploy Part Pilot when application source changes. Verify Alembic, run the complete smoke suite, verify relevant protected APIs, verify SPA routes, and verify deployed markers. Restore source and the previous deployment safely if any step fails.

Browser-test workflow:
Do not include browser-test instructions inside Python scripts.
First provide the script. The user runs it and reports terminal results. Terminal Everything PASS means automated verification only, not browser approval. Provide browser-test instructions separately when required. Keep browser-test changes uncommitted and unpushed until the user explicitly approves the browser result. Apply feedback through the next sequential Python script. After explicit approval, create a separate checkpoint/commit/push script.

Git workflow:
Check local git status before assuming GitHub is current. Commit each small independently approved batch and push it promptly. Stage only intended files, verify the exact staged file set, run staged git diff --check, commit with a focused message, push main, fetch, and verify local and origin/main point to the same commit.
